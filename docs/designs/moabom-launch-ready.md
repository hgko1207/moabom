## Problem Statement
모아봄은 아내에게 "영상 카드라는 게 있다"는 말만 듣고 만들었다. 이제 실제 사이트(https://video-cards.pages.dev/)를 받았고, 완성도가 높다. 목표는 두 가지다. 하나는 우리 가족이 계속 쓰는 것이고, 다른 하나는 다른 부모에게 알려 인스타그램·네이버로 홍보하는 것이다. 영상 카드를 기능 단위로 전부 분석해서 세 가지로 나눈다.
- 가져올 것
- 구조를 고칠 것
- 영상 카드에도 없는 더 나은 것

## 영상 카드 분석 요약 (근거)
- **구조는 모아봄과 같다.** 개발자가 채널과 영상을 정해 두고, 부모는 기기에서 켜고 끄기만 한다. 앱 안에서 영상을 검색하거나 링크로 담는 기능은 없다. 코드에는 "내 카드"(`/my/`)가 있지만 아직 배포되지 않았다.
- **규모와 만든 방식**
  - 18채널, 2,695편을 손으로 큐레이션한다. YouTube Data API는 쓰지 않는다.
  - ES5 바닐라 JS이고, 채널 종류마다 app.js 사본이 5개 있다. 사본끼리 이미 어긋나 있다(노래판에는 길이 뱃지가 빠짐).
  - 저장은 localStorage뿐이다.
  - 통계는 GoatCounter(쿠키 없음)로 센다. 쿠팡 제휴는 엄마 문 뒤에만 있다.
- **강점**
  - 엄마 문: 한글로 쓴 숫자를 숫자판으로 입력한다.
  - 요일 계획과 "엄마가 오늘만 열어 주기", +N편 더 열어 주기
  - 이전 편 / 한 번 더 / 다음 편, 속도, 자막
  - 구간 카드(`영상ID@시작-끝`)
  - 넘버블록스 한↔영 짝(한국어판 120편 + 영어판 189편)
  - OS가 멈춘 영상 자동 재개, 오류가 나면 3초 뒤 다음 영상으로 넘김
  - 편마다 손으로 쓴 한 줄 설명. 재생 화면에는 "이번 편 이야기"로 나온다.
  - 채널마다 색 변수(`--c`) 하나로 테마를 바꾼다.
  - 인앱 브라우저 탈출(카톡, 인스타, 네이버, 라인 등), 이용 안내·개인정보 화면, 새 소식 NEW 표시, 아이 이름이 들어간 제목
- **약점** (모아봄이 이미 해결한 것에 ✔)
  - 하루 제한이 채널마다 따로다. ✔ 모아봄은 프로필 전체에 걸림
  - 분 단위 제한이 없다. ✔
  - 다른 영상으로 빠져나가는 것을 감지하지 못한다. ✔ P2
  - 영상이 지워지면 손으로 고쳐야 한다. ✔ 매주 자동 갱신
  - 백업·동기화가 없다. ✔ 설정 보내기
  - 엄마 문 잠금이 새로고침하면 풀린다.
  - 첫 실행 때 설정이 엄마 문 없이 열린다.
  - 잠자리 시간 잠금이 없다.
  - 접근성이 없다(줌 막힘, 동작 줄이기 미대응).
- 받아 둔 원본은 세션 scratchpad의 `vc-site/`에 있다(임시 폴더).

## What Makes This Cool
**"고를 필요가 없다."**
- 유튜브 키즈의 "승인된 콘텐츠만" 모드와 해외 도구들(WhitelistVideo, Kivvie, Streamu)은 부모에게 직접 고르라고 숙제를 준다.
- 모아봄은 이 셋을 이미 해 두었다.
  - 공식 채널만 검증해서
  - 순서대로(순서 = 학습 경로) 정리하고
  - 매주 자동으로 갱신한다.
- 거기에 캐릭터를 바꿔도 이어지는 하루 제한이 있다.
- 이 정체성을 아이 쪽까지 밀어붙인 것이 v2 후보인 "우리집 방송국 편성표"다.

## Constraints
- SPEC v4 원칙을 그대로 지킨다.
  - 공식 채널만, 주제 중립 엔진, 특정 컬렉션을 코드에 넣지 않는다.
  - 새 컬렉션은 설정 파일만으로 추가한다.
  - API 키를 클라이언트에 노출하지 않는다.
  - Lucide 아이콘과 Pretendard를 쓰고, 이모지를 디자인 요소로 쓰지 않는다.
- 서버가 없는 정적 GitHub Pages 구조를 유지한다.
  - Data API는 빌드 때만 부른다. 그래서 사용자 수가 할당량에 영향을 주지 않는다.
  - **클라이언트에서 Data API를 부르는 기능은 만들지 않는다.** 검색 한 번이 100유닛이라, 전체 사용자를 합쳐 하루 100번이면 할당량이 바닥난다.
- 우리 집은 6세·4세 두 아이가 공용 프로필 하나를 쓴다. 4세는 글을 못 읽는다.
- 채널 ID는 사용자가 확인한 뒤에만 설정에 쓴다(`/add-character`).
- 핑크퐁·뽀로로·타요는 사용자가 요청할 때까지 넣지 않는다.

## Premises (합의됨)
1. 큐레이션은 개발자 쪽에서 하고, 빌드 때 굳힌다.
   - 콘텐츠는 사용자가 고른다. 우리 아이들이 보고 싶은 것, 다른 부모의 요청, 사용자의 선별이 기준이다.
   - 부모가 앱에서 직접 담는 기능은 만들지 않는다.
   - [D4 수정] 두 번째 의견이 "요청이 쌓일 때까지 기다리면 조용히 떠나는 부모를 놓친다"고 반박했다. 사용자는 주류 채널을 한꺼번에 넣는 안 대신 "카테고리로 묶고, 고른 것만 넣는다"를 택했다. 그래서 이탈은 통계(P1-7)로 지켜본다.
2. 널리 알리기 전에 다음이 있어야 한다: 엄마 문, 이용 안내, 인앱 브라우저 탈출, 요청 창구와 소식.
3. 디자인은 이모지나 주아체로 바꾸지 않는다. 대신 캐릭터별 고유색으로 따뜻함을 더한다.
4. `src/main.ts`(1,171줄)는 **손대는 화면부터** 나눈다. 1단계에서 설정·홈을 고치므로 그 둘을 먼저 나누고, 컬렉션·플레이어 화면은 2단계에서 고칠 때 나눈다. [리뷰 R1-15]
5. 재생 화면에 이전 편 / 한 번 더 / 다음 편 / 자막 버튼을 넣는다.
   - 처음에는 전부 꺼져 있고, 부모가 설정에서 켠다.
   - 자막은 켜도 영상마다 기본은 꺼짐이다.
6. 카드와 재생 화면에 제목, 소제목(편 라벨), 한 줄 설명을 보여 준다.
   - 설명은 주력 시리즈부터 AI 초안을 만들고 부모가 확인해서 채운다.
   - 설명이 없는 편은 설명 없이 보여 준다.
7. 이름은 "모아봄"을 유지한다.
   - 로고, 로고 글꼴, 한 줄 소개를 만든다.
   - 첫 화면은 로고 + "○○네 모아봄"이다.
   - 캐릭터 그림은 로고와 홍보물에 쓰지 않는다.
8. 홍보의 핵심 메시지는 "고를 필요가 없다"다.

## Cross-Model Perspective
독립 Claude 서브에이전트에게 요약만 주고 의견을 받았다. Codex는 설치되어 있지 않다.

- **가장 멋진 버전: "우리집 방송국" 편성표**
  - 앱이 매일 TV처럼 편성한다. "1교시 넘버블록스 → 2교시 블루이 → 달 화면" 식이다.
  - 학습 먼저, 요일, 하루 제한, 잠자리, 형제 차례, 스티커, 목소리 안내가 하나로 합쳐진다.
  - `rules.ts`의 `nextToWatch`·`orderCollectionIds`와 `TodayState`를 그대로 쓸 수 있다.
  - "우리집 편성표 공유" 카드는 입소문 장치가 된다.
- **반박한 전제: 1번** (High)
  - 지금 콘텐츠는 영어·수학 교육물 위주다.
  - 맞는 프로가 없는 부모는 요청하지 않고 떠난다.
  - 검증 기준: 홍보 첫 2주의 "방문 → 첫 재생" 전환율이 30% 미만이고, 폼 제출이 방문의 1% 미만이면 반박이 맞다.
- **차점: 6번(편당 설명)** (Medium). 4세는 글을 못 읽는다.
  - 판단: 설명은 부모용이므로 유지하되, 2단계로 미룬다.
- **기존 도구로 대신할 수 있는 절반**
  - GoatCounter(통계)
  - `inapp-spy`(인앱 브라우저 판별). 단, 우리 `install.ts`에 이미 정규식이 있다.
  - privacy.go.kr 처리방침 만들기
  - IFrame `start`/`end`(구간 카드)
  - `speechSynthesis`(목소리 안내)
  - 눈누의 상업적 이용 가능한 무료 글꼴(로고)
- **주말 작업 순서**: OG 메타 → 인앱 탈출 → 설정 화면 분리 → 개인정보 → GoatCounter → 요청·소식 → 엄마 문
- **코드로 확인한 것**
  - `index.html`에 og 태그가 0개다.
  - 인앱 탈출은 `index.html:20`에서 카톡만 처리한다.
- **고쳐서 받아들인 제안**: 엄마 문의 **해제 상태**는 서브에이전트 말대로 메모리에만 둔다(새로고침하면 다시 잠김). 다만 **틀려서 걸린 잠금**은 저장한다. 영상 카드는 이 실패 잠금까지 메모리에 둬서 새로고침하면 풀린다(P1-4).

## Approaches Considered
- **A. 홍보 준비만** (CC 약 하루): 빠르지만 재생 화면이 밋밋하다. B의 1단계로 흡수했다.
- **B. 단계별 완성판** (CC 약 3~4일): **선택.**
- **C. 우리집 방송국 편성표** (CC 약 1주): 홈 구조를 바꾸는 큰 베팅이다. 아이 반응과 통계를 본 뒤 v2 후보로 둔다.

## Recommended Approach: B. 단계별 완성판
단계마다 따로 배포한다. 1단계가 끝나면 바로 홍보를 시작한다.

### 1단계: 홍보 준비 (홍보를 막는 것)
- **P1-1 링크 미리보기**
  - `index.html`에 OG·트위터 메타를 넣고, `public/og.png`(1200×630)를 만든다.
  - 그림은 로고와 한 줄 소개만 쓰고, 캐릭터 그림은 넣지 않는다.
- **P1-2 인앱 브라우저 탈출 확대** [R1-1, R1-2]
  - **인앱 브라우저만** 잡는 정규식을 새로 만든다: KAKAOTALK, Instagram, NAVER, Line/, FBAN/FBAV, DaumApps, BAND, everytimeApp 등. iOS와 안드로이드에 같이 쓴다.
  - 설치 안내용 "iOS의 Safari가 아닌 브라우저" 판별(`IOS_NOT_SAFARI`)과는 분리한다. Chrome·Firefox·웨일 같은 진짜 브라우저는 탈출 대상이 아니다.
  - ~~정규식은 `src/inapp.ts` 한 곳에 둔다. `index.html`의 인라인 스크립트는 모듈보다 먼저 동기로 돌아야 하므로, Vite `transformIndexHtml` 플러그인으로 **빌드할 때 인라인 스크립트에 주입**한다.~~ [superseded by eng D2: 정규식은 index.html 인라인 스크립트에만 두고, tests/inapp.test.ts가 그 스크립트를 직접 실행해 검사한다]
  - 탈출 동작
    - 카톡: 지금처럼 `kakaotalk://web/openExternal`
    - 안드로이드: Chrome `intent://`로 열고, `S.browser_fallback_url`을 붙인다(Chrome이 없을 때 대비).
    - iOS(카톡 제외): "Safari로 열기" 안내와 주소 복사를 띄운다.
  - 탈출 URL은 쿼리(`?ref=` 등)를 그대로 유지한다.
  - `tests/install.test.ts`(또는 `tests/inapp.test.ts`)에 테스트를 넣는다.
    - 인앱 UA는 잡힌다.
    - 진짜 브라우저 UA는 잡히지 않는다.
    - 빌드된 인라인 스크립트와 모듈의 정규식이 같다.
- **P1-3 화면 분리 (1차)** [R1-15]
  - 설정·기록 화면(`renderSettings`, `renderHistory`)을 `src/screens/settings.ts`로, 홈 화면(`renderCollections`)을 `src/screens/home.ts`로 옮긴다.
  - 1단계 작업(P1-4~P1-9)이 이 두 화면을 고치기 때문이다.
- **P1-4 엄마 문** [R1-4, R1-5, R1-6]
  - 톱니를 2초 누른 뒤 문제를 푼다. 숫자판에는 ⌫가 있다.
    - 기본 문제: 한글로 쓴 **세 자리 수**(예: "삼백이십칠")를 숫자로 누른다.
    - 6세는 한글을 읽으므로 이 문제가 6세를 막는다는 근거는 아직 없다.
    - 시험 절차: P1-4 구현 뒤, 홍보 전에 6세에게 세 자리 문제를 10번 시도하게 한다. 한 번이라도 통과하면 대안 문제(한글로 쓴 덧셈, 예: "십칠 더하기 이십오")로 바꾸고 같은 시험을 다시 한다. 이 시험을 통과해야 1단계 완료다.
  - **해제 상태**는 메모리에만 둔다. 설정 화면을 떠나거나 5분이 지나면 끝나고, 새로고침하면 다시 잠긴다.
  - **실패 잠금**
    - 3번 틀리면 30초, 그 뒤로도 틀리면 최대 5분까지 늘어난다. 5분을 넘지 않는다.
    - localStorage에 저장해서 새로고침해도 풀리지 않는다.
    - 날짜가 바뀌면 초기화한다. 설정 보내기 링크에는 넣지 않는다.
  - 잠긴 동안에는 "N초 뒤에 다시 할 수 있어요"를 보여 준다. 부모의 복구 경로는 "최대 5분 기다리기"뿐이고, 사이트 데이터 삭제는 기록까지 지우므로 안내하지 않는다.
  - 틀림 표시는 흔들림 없이 "다시 해 보세요" 한 줄(디자인 리뷰 DR7).
  - 쓰는 곳: 설정 열기, "오늘만 더"(P2-3), ~~외부로 나가는 모든 링크(P1-5, P1-6)~~ [superseded by DR10: 외부 링크는 모두 설정 안(이미 엄마 문 뒤)에 있어 다시 묻지 않는다]
- **P1-5 이용 안내·개인정보** [R1-7, R1-8]
  - **설정 안(엄마 문 뒤)**에 앱 안의 안내 화면(`#/p/{pid}/about`)으로 둔다. 첫 화면 같은 아이 화면에는 외부 링크를 두지 않는다.
  - 내용은 실제 데이터 흐름대로 쓴다.
    - "시청 기록, 진도, 설정은 이 기기의 브라우저에만 저장되고 어디로도 보내지 않아요."
    - "영상은 YouTube가 재생해요(youtube.com 플레이어). 이 기기에서 YouTube에 로그인해 있으면 YouTube가 시청 정보를 받을 수 있어요." 그리고 YouTube 이용약관과 Google 개인정보처리방침 링크(YouTube API 정책 III.A)
    - 익명 통계: GoatCounter로 보내는 **필드 목록**을 그대로 적는다(P1-7). 쿠키는 쓰지 않는다. IP 처리 방식은 GoatCounter 정책을 링크한다.
    - "각 채널(제작사)의 공식 서비스가 아닌, 개인이 만든 무료 도구예요."
- **P1-6 요청 창구와 소식** [R1-5, R1-7]
  - "캐릭터·영상 추천하기"(구글 폼) 링크는 **설정 안에만** 둔다. 아이가 보는 "오늘은 여기까지" 화면에는 두지 않는다.
  - 소식은 `config/news.json`에 적고 빌드에 포함한다.
    - 새 소식은 설정 안의 맨 위 카드로 보여 준다. 읽음 여부는 기기별로 저장한다.
    - **톱니에 NEW 점을 띄우지 않는다.** 아이가 톱니를 누르게 만들기 때문이다.
- **P1-7 익명 통계 (GoatCounter, 쿠키 없음)** [R1-9, R1-10]
  - 홍보 링크에는 경로 표시를 붙인다: `?ref=insta`, `?ref=naver`, `?ref=kakao`. 앱은 첫 방문 때 이 값을 sessionStorage에 담아, 이벤트마다 함께 보낸다.
  - 이벤트와 필드
    - `visit`(ref): 홈 방문, 세션당 1회
    - `first_play`(ref, collectionId): 그 세션의 첫 재생, 세션당 1회
    - `play_start`(collectionId)
    - `limit_reached`(mode)
    - `video_error`(videoId, code)
    - `collection_open`(collectionId)
    - `request_click`: 추천하기 링크 클릭
    - `inapp_escape`(앱 종류)
  - 아이 이름, 설정 내용, 기록은 보내지 않는다.
  - **인앱 브라우저에서 탈출하는 페이지는 `visit`을 세지 않고 `inapp_escape`만 보낸다.** 한 사람이 두 번 세지지 않게 하기 위해서다.
  - **우리 가족 기기 제외**: 설정에 "익명 통계 보내기" 스위치(끄면 이 기기는 안 보냄, DR19)를 두고 localStorage에 저장한다. 우리 집 기기에서는 꺼 둔다.
  - 전환율 정의: ref별 `first_play` 수 ÷ `visit` 수. 쿠키가 없으므로 사람 단위 퍼널이 아니라 이벤트 수의 비율로 본다.
  - 요청 수의 출처: 구글 폼 응답 수. 보조로 `request_click` 수를 본다.
- **P1-8 카테고리** [R1-11, R1-13]

    - `icon`: Lucide 이름. `src/icons.ts`에 있는 허용 목록만 쓸 수 있다.
    - `color`: `#RRGGBB`
  - 컬렉션 설정에 `category`(필수)를 넣는다. 모르는 카테고리, 허용 목록에 없는 아이콘, 형식이 틀린 색은 검증 오류로 막는다.
  - 홈 배치 규칙
    - 카테고리 줄 순서는 `categories.json` 순서를 따른다.
    - 줄 안의 캐릭터 순서는 부모가 정한 순서(`order`)를 따른다.
    - 숨긴 캐릭터는 빠지고, 보이는 캐릭터가 0개인 카테고리 줄은 숨긴다.
    - 보이는 카테고리가 2개 이상일 때만 줄로 나누고, 1개면 지금처럼 한 그리드로 보여 준다.
    - 설정의 "보여 줄 캐릭터"도 같은 카테고리별로 묶어 보여 준다.
  - `/add-character` 스킬에 "카테고리 고르기(또는 새 카테고리 추가)" 단계를 넣는다.
  - 처음 나누는 안은 아래와 같고, 사용자가 바꿀 수 있다.

    | 카테고리 | 캐릭터 |

    | 숫자·글자·색 | 넘버블록스, 알파블록스, 컬러블록스 |
    | 이야기 | 블루이, 옥토넛 |
    | 생활·동화 | 깨비키즈 |
- **P1-9 정체성** [R1-16]

### 2단계: 재생 화면과 정보
- **P2-1 재생 버튼: 이전 편 / 한 번 더 / 다음 편 / 자막** [R1-17, R1-19]
  - 기기 설정에서 하나씩 켜고 끄며, 기본은 모두 꺼짐이다. 켠 상태는 설정 보내기에 포함한다.
  - 다음 편·이전 편은 새 편을 시작하는 것이라 기존 하루 제한 검사(L3)를 그대로 거친다.
  - "한 번 더"
    - 같은 날 다시 보는 것이라 편수에 새로 세지 않는다(L1).
    - 분 제한에서는 다시 본 시간도 실제 재생 시간이므로 센다(L2).
    - **하루 제한에 닿은 뒤에는 숨긴다.** L3a는 "아직 완료되지 않은 편"만 다시 열 수 있게 하는데, 한 번 더는 방금 다 본 편이기 때문이다.
  - 자막
    - `cc_load_policy` 기본은 0이다.
    - **구현 전에 짧게 확인(spike)한다**: iPad Safari와 안드로이드 Chrome에서 `loadModule('captions')`/`setOption('captions','track',…)`이 동작하는지 본다. 이 둘은 공식 문서에 없는 기능이다.
    - 자막 유무는 fetch 때 videos.list의 `contentDetails.caption` 값을 레코드의 `hasCaptions`로 저장해서 판단한다. `hasCaptions`가 false인 영상에서는 자막 버튼을 숨긴다. 비공식 기능에 기대지 않는다.
    - spike가 실패하면 대안으로 간다. `cc_load_policy`는 플레이어를 만들 때만 정할 수 있으므로, 대안은 플레이어를 다시 만들어 현재 시각부터 이어 트는 방식이다.
    - 다시 만드는 동안의 처리
      - 앱이 다음 화를 불러올 때처럼 다른 영상 감지(P2)는 첫 PLAYING까지 비교를 생략한다.
      - 같은 편이므로 편수에 새로 세지 않는다.
      - 진도 위치는 그대로 이어 간다.
- **P2-2 제목·소제목·설명**
  - 카드: 편 라벨(예: "12화", "시즌 2·5화") + displayTitle
  - 재생 화면: 제목 + 라벨 + 한 줄 설명
  - 설명은 `config/descriptions/{collectionId}.json`(videoId → 문장)에 둔다. AI 초안을 만들고 부모가 확인하며, 주력 시리즈부터 채운다.
  - 설명이 없으면 그 줄을 숨긴다.
- **P2-3 오늘만 더** [R1-18]
  - 엄마 문 뒤의 달 화면과 설정의 "오늘" 칸에 둔다.
  - 제한 방식에 따라 다르게 동작한다.
    - 편 제한: +1·+2·+3편
    - 분 제한: +10·+20·+30분
    - 제한 없음: 버튼을 보이지 않는다.
  - `today.extraEpisodes`·`today.extraSeconds`로 저장한다. `limitReached`는 "제한 + extra"로 계산하고, 날짜가 바뀌면 사라진다.
  - `rules.ts`에 들어가므로 단위 테스트를 쓴다.
- **P2-4 OS가 멈춘 영상 자동 재개** [R1-20, R1-21]
  - 판별 규칙: 화면으로 돌아왔을 때(`visibilitychange`가 visible) 아래 셋이 **모두** 참일 때만 `playVideo()`를 부른다.
    - (a) 가려질 때 PLAYING 상태였다.
    - (b) PAUSED 이벤트가 가려진 동안, 또는 가려진 직후 1초 안에 왔다.
    - (c) 가려져 있던 시간이 60초 미만이다.
  - 앱 안에서 사용자가 누른 일시정지는 기록해 두고, 그 경우에는 재개하지 않는다.
  - 화면을 60초 넘게 잠갔거나 꺼 두었으면 재개하지 않는다. 엄마가 화면을 잠가서 멈춘 경우는 이 규칙으로 걸러진다.
  - `playVideo()`가 막혔을 때(iOS 자동 재생 정책 등, 1초 뒤에도 PLAYING이 아님)는 영상 위에 큰 재생 버튼을 띄운다.
- **P2-5 영상 오류 처리** [R1-22]
  - 실패한 영상은 편수와 시간에 넣지 않는다(지금 P4와 같음).
  - 3초 뒤 넘어갈 다음 편은 지금 "다음 화" 규칙(P3·`upNext`)으로 정하고, 하루 제한(L3)을 거친다.
    - 다음 편이 없거나(컬렉션 끝) 제한에 걸리면 자동으로 넘기지 않고, 지금 오버레이를 보여 준다.
    - free 그룹은 지금처럼 같은 탭 안에서만 다음 편을 찾는다.
  - 오류 코드에 따라 `failed`에 기록하는 시점이 다르다.
    - 100/101/150(영상이 지워짐, 임베드가 막힘): 영상 문제이므로 지금처럼 즉시 `failed`에 기록한다.
    - 2/5 또는 `navigator.onLine`이 false인 경우
      - 인터넷이나 일시적 문제일 수 있어 **보류 목록**에 넣는다.
      - 다음 영상이 정상 재생되면 보류한 영상을 `failed`로 확정한다.
      - 2/5가 연속 3회이거나 offline이면 보류 목록을 버린다(⚠ 흐림이 남지 않음). 그리고 "인터넷 연결을 확인해 주세요"를 보여 준다.
  - 100/101/150이 연속으로 나는 경우는 인터넷 문제가 아니므로, 연결 안내를 띄우지 않고 다음 편으로 계속 넘긴다.
- **P2-6 색 규칙 (캐릭터 고유색 포함)** [R1-12]
  - 컬렉션 설정에 `color`(선택)를 둔다.
  - 색이 쓰이는 곳
    - **프로필 색**: 홈과 프로필 화면의 `--accent`(포커스 링, 홈 이어 보기 테두리)
    - **컬렉션 색**: 그 컬렉션 화면과 플레이어 안에서 `--accent`를 대신한다(탭, 오늘 볼 영상 테두리, 포커스 링). 없으면 프로필 색을 쓴다.
    - **카테고리 색**: 홈의 카테고리 줄 제목 앞 아이콘 표시에만 쓴다.
  - 본문 글자색으로는 쓰지 않는다는 원칙은 유지한다.
  - 대비 검사는 프로필 색, 컬렉션 색, 카테고리 색 세 가지 모두에 같은 기준을 적용하고, 설정 검증에서 계산한다.
    - 색 위에 흰 글자를 올리는 곳 중 일반 글자(편 번호 뱃지 등, 24px 미만)는 4.5:1, 큰 글자(탭 숫자 32px 700 등)는 3:1. 실제로 흰 글자가 올라가는 곳은 이 두 가지뿐이라고 정한다.
    - 테두리·채움만 쓰는 곳은 `--bg`(#F4F6FA)와 `--surface`(#FFFFFF)에 대해 3:1. 달 화면(`--night`)에서는 이 색들을 쓰지 않는다.
    - 지금 프로필 색 #4C8BF5는 흰 글자와 약 3.3:1이라 일반 글자 기준에 못 미친다. `--ink`(#1B2230)와는 약 4.8:1이라 통과한다.
    - `src/styles.css`는 강조색 채움 위에 대부분 `--ink` 글자를 쓴다. 그런데 920·1028·1176행 근처 세 곳은 흰 글자 15~16px을 써서 이미 기준 미달이다. 이 세 곳을 `--ink` 글자로 바꾼다.
    - 규칙: 강조색 채움 위의 일반 글자는 `--ink`, 흰 글자는 큰 글자에서만 쓴다. 미달 색은 빌드 오류로 막는다.
  - SPEC v5에서 §10 "강조색은 프로필 색 하나"를 위 규칙으로 고친다.
- **P2-7 화면 분리 (2차)**: 2단계에서 고치는 컬렉션 화면과 플레이어 화면을 나눈다.

### 3단계: 콘텐츠
- **P3-1 넘버블록스 영어 공식 채널과 한↔영 짝** [R1-23]
  - **먼저 확인한다**: 한국어판과 영어판에서 5편을 표본으로 골라, 편 번호가 같은 이야기를 가리키는지와 길이 차이를 본다.
  - 짝 정하기
    - 번호가 맞으면 설정의 `pair`(상대 컬렉션 ID)로, 편 번호가 같은 영상끼리 짝을 짓는다(draft-groups의 편 번호 패턴을 재사용).
    - 번호가 어긋나면 수동 매핑 파일 `config/pairs/{id}.json`(한국어 ID → 영어 ID)을 쓴다.
  - 재생 화면에 "같은 편 영어로" 버튼이 생긴다.
    - 두 영상의 길이 차이가 5% 이내면 보던 장면 2초 전부터 이어 튼다.
    - 그보다 크면 처음부터 튼다. 더빙판과 원판의 장면 시각이 맞는다는 보장이 없기 때문이다.
  - `rules.ts` 변경: 오늘 편수를 셀 때 영상 ID 대신 "짝 키"(짝이 있으면 둘 중 정해진 ID)로 중복을 빼서, 짝을 1편으로 센다. 단위 테스트를 쓴다.
- **P3-2 구간 카드** [R1-24]
  - `videos` 배열에 `영상ID@시작초-끝초`를 허용한다.
  - 레코드에 두 키를 나눈다.
    - `id`: `영상ID@시작-끝`. 진도(watched, position), 오늘 started, 기록의 키로 쓴다. 같은 영상의 다른 구간끼리 섞이지 않는다.
    - `sourceId`: 원래 영상 ID. 썸네일, `videos.list` 호출, 플레이어 로드에 쓴다.
  - 길이와 완료 판정은 **구간 길이**(끝 − 시작)를 기준으로 한다(O1의 90%). 재생은 `start`/`end` playerVars로 하고, 이어 보기 위치는 구간 안의 시각이다.
  - 검증은 두 단계로 나눈다.
    - 설정 검증: 형식, 시작 < 끝
    - fetch: 끝 ≤ 영상 길이. 넘으면 그 카드를 빼고 경고한다.
- **P3-3 후보 채널** (`/add-character`로 공식 채널을 확인받은 뒤 추가)
  - 한글이 야호(EBS): "한글" 카테고리를 새로 만든다.
  - 페파피그: 한국어판 공식 채널이 있는지 확인한다.
  - 슈퍼 심플 송: "영어 동요" 카테고리를 새로 만든다.
  - 다니엘 타이거, 티미 타임, 찰리와 롤라
  - 구간 카드가 생긴 뒤: 미스 레이첼, 맥스앤루비, 까이유
